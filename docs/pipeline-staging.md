# Pipeline source and remaining integration

The pipeline is app orchestration through injected task ports. It does not implement or
vendor S3 providers/accounting or S6 screening. There is no shipping mock/replay/live backend
default. Test doubles are authored fixtures and never establish a model result or calibrated
screening/semantic accuracy. Actual owner publication, licence and moved-copy checks remain
required before shipping integration.
Execution origin is explicit; generation and semantic results must match it. Mock, recorded
replay and live results cannot be relabelled into one another, and live policy cannot use
an offline rules screen.

All possible plan/repair/support stages need explicit CallBindings before the first port
call. Every stage retains the same caller-owned ledger, budget and allocation objects,
with its own matching purpose/context and caller limits: at most two transport attempts,
zero provider content repairs. This is object/shape admission at the app seam, not proof
that an owner operation is funded. S3 performs real whole-operation admission, retries,
settlement, cumulative caps and liability preservation. No key lookup, SDK, controller,
cache, price calculation or budget reset is implemented here.

Planning accepts only MetricSnapshot and a bounded brief. It selects up to 40 citable rows
using deterministic round-robin platform/dimension buckets, reports total/selected counts,
and assembles the complete request before screening. No raw post rows/text or private Gold
are appended. Oversized original or normalized assembly, wrong digest/generation/policy/
method, coverage gaps, actual safety flags or unavailable required methods stop downstream
calls. Diagnostic notices never clear a safety flag. Typed-live projections also require
operating authority/accounting references; those labels alone are not a live grant.

Every candidate passes exact structural/evidence/numeric checks before batched semantic
review. The semantic answer IDs must cover exactly the submitted items. Only supports
survives. Rejected content may be regenerated once using codes and the same table, with
no rejected raw body in the repair request. Holds/unavailable required support stop further
stages. Fewer than five survivors remains explicit underfill; no citable metrics returns
empty without any port calls. Proposed/repair/drop counts are retained.

Draft orchestration requires the exact currently approved parent from host authority,
checks it again after generation and before disclosure, inherits its scope/citations and
pins the parent revision. The resulting code-rendered body passes target, screening and
semantic checks. A parent edit or source-generation change during generation discards the
body and blocks later model calls. The actual generic store is used in local two-approval/
receipt tests; API/browser/provider acceptance remains separate. X stays unsupported until
its parser/official vectors pass; LinkedIn conservatively counts at most 3,000 UTF-16 units.

Supplied topic/format labels remain unchanged. Keyword and untagged baselines are explicit
local code, not measured classifiers. Optional Luna/Jev task ports receive only minimal
per-post text and taxonomy after a complete input screen. Typed thresholds are explicitly
configured exact decimals; low confidence/unavailable/held results abstain while retaining
the post and provenance. Primitive confidence preserves finite numeric precision and is
separate from the eight-place metric wire. The app has no automatic Jev-default selection.
Selection awaits the approved matched-task dev/held-out measurements.

The TypeSafe [Choice](https://docs.typesafe.ai/primitives/choice),
[confidence](https://docs.typesafe.ai/confidence) and
[citation-checking](https://docs.typesafe.ai/cookbooks/citation_check) docs were consulted.
Actual SDK/version/response conformance and paid authority remain S3 integration gates.
